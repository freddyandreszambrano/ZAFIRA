# Auditoría de reglas — 2026-07-13

## Contexto y precedencia

La auditoría compara Zafira con `C:\HEY\ANDROID\hey-support\ai`. La fuente de verdad para este
repositorio es: código y configuración versionados de Zafira, `AGENTS.md`, `ai/rules/`,
`ai/PATTERNS.md` y este documento; la guía de hey-support aporta reglas transversales, pero no sus
rutas, módulos ni sabores específicos.

Cuando las guías difieren, Zafira adopta este contrato:

```text
Widget → Controller → UseCase → IRepository ← Repository → Service → DioHttpClient
```

Los servicios ejecutan HTTP y convierten la respuesta inmediatamente a un tipo concreto. Los casos
de uso son la única capa que traduce errores a `Either<Exception, T>`. No se mezclan ambos patrones.

## Resultado final

Los 15 controles auditados cumplen. La app queda con una base verificable de arquitectura, tipado,
UI y pruebas; no hay excepciones pendientes derivadas de esta auditoría.

## Cambios estructurales realizados

- Onboarding recibió sus capas completas y ya no llama a `AuthController`.
- Home recibió sus capas completas y ya no depende de `CatalogController` para cargar productos.
- Perfil y gestión de foto se integraron a Auth, que es su límite de sesión natural.
- `HomeBottomNav` e `ImagePickerService` se movieron a infraestructura compartida.
- `ProductModel` se promovió a `core/models/` y se actualizaron sus consumidores.
- Se retiraron `SharedPref` y `DaoSQL`, código legacy sin usos que conservaba `dynamic` y navegación imperativa.
- Se tiparon requests/responses Dio y se añadió inyección de Dio para pruebas de servicio aisladas.
- Los casos de uso de token, guardado, borrado y comprobación de sesión ahora retornan `Either`.

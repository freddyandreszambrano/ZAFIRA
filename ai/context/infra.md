# Infrastructure Context

## CI/CD - GitHub Actions

| File | Purpose |
| --- | --- |
| `.github/workflows/ci.yml` | Quality gate and debug Android builds for both flavors on PRs and pushes. |
| `.github/workflows/android-release.yml` | Manual signed APK/AAB release, optionally published as a Shorebird base release. |
| `.github/workflows/shorebird-patch.yml` | Manual OTA patch for an exact Shorebird base release. |

The CI pipeline has no release secrets. Signed builds execute only in the
`development` or `production` GitHub Environment. See `docs/android-release.md`
for the required secrets, signing setup, and release commands.

## Flutter Version Management

- Flutter is pinned to `3.41.9` in `.fvmrc` and CI.
- Run `fvm install` after changing the pin or if the local SDK does not match it.
- Use `fvm flutter` locally; workflows install the same version directly.

## Android and OTA distribution

- Flutter creates signed APK/AAB artifacts.
- Shorebird creates the patchable base release and Dart-only OTA patches.
- `shorebird.yaml` is generated by `shorebird init --force`, committed, and has
  a separate app ID for `dev` and `prod`.
- Android signing materials and API URLs are injected as GitHub Environment
  secrets and must never be committed.
